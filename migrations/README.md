# Міграції бази даних

З цього моменту схема БД керується через **Alembic**, не вручну написаним SQL.

## Як застосувати міграції (на новій або вже існуючій базі)

```bash
export DATABASE_URL="postgresql+asyncpg://..."   # той самий, що для main.py
alembic upgrade head
```

## Як створити нову міграцію після зміни моделей у app/models/

```bash
alembic revision --autogenerate -m "короткий опис зміни"
```

**Важливо:** завжди відкрийте згенерований файл у `alembic/versions/` і перевірте
вручну - autogenerate не бачить exclusion constraints, RLS-політики, тригери,
і іноді плутає порядок таблиць при циклічних зв'язках (як було з users/businesses
у першій міграції). Перевірте, прогоніть на тестовій базі, і лише тоді - на проді.
